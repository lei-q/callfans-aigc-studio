# AIGC 创作台原型文档

> 版本：v0.27  
> 更新：2026-10-18 01:20（GMT+8）  
> 原型入口：[index.html](./index.html)

## 1. 产品目标

**定位：不用订阅，按次付费，说一句就能出片。**

面向不需要天天用 AI、但有突发需求的个人用户：今晚要发的小红书封面、明天要交的详情页配图、突然要一条口播。他们不想为一次需求买月费，只想充一点、把当下的事解决掉，然后一直留着这个工具。

判断依据很简单：这类用户打开工具时脑子里只有一句「我现在要一张能直接发出去的素材」，他们对「管理」没有兴趣，对「被套住」很敏感。

### 1.0 用户与付费心理

| | 普通用户（主力） | 专业用户（长尾） |
| --- | --- | --- |
| 打开方式 | 网页 | API Key，接进 agent、脚本或批量工具 |
| 典型频率 | 低频、突发，一个月几次 | 按项目批量跑 |
| 付费心理 | 「充 10 块试试，能用再充」 | 「算算一张多少钱，比跑本地划算吗」 |
| 决策障碍 | 怕被套：怕充了不能用、怕点数过期、怕图不能退 | 怕限速、怕欠费断服、怕接口变 |

**关于「薅羊毛」**：价格敏感用户去比价、找免费额度是必然行为。与其防，不如把它设计成获客漏斗——每日免费点数、首充翻倍、新人礼包。薅的人就是 DAU 与口碑渠道，防的人会变成差评来源。

### 1.0.1 因此不做什么

原型明确**不做**企业治理能力：没有团队工作空间、没有额度池、没有审批流、没有合规确认。个人用户要按项目拆分，所以保留了「项目」（原来的工作空间概念），但它只是一个分类维度，没有成员、没有配额、没有审批。

### 1.1 核心痛点与对应设计

绝大多数目标用户不是提示词工程师，他们对工具的真实诉求是：**“我有个想法，想快点拿到能用的素材”**。真正卡住他们的是三件事：

1. **写不出提示词**：面对空白输入框不知道该写什么，写出来的又太短，模型给的结果不可控。
2. **不知道该选什么**：模型、比例、数量、分辨率、时长、运镜……十来个选项，每个都要犹豫。
3. **等的时候心里没底、挑的时候拿不定主意**：不知道要等多久，出来几张又不知道该选哪张。

原型 v0.4 起直接回应这三点：

| 痛点 | 设计回应 |
| --- | --- |
| 写不出提示词 | 输入一句大白话即可，点「帮我写详细」由系统补成完整提示词；描述已经够长时按钮自动变为「补充细节」。字数提示会实时告诉用户当前描述是否完整。 |
| 不知道选什么 | 参数区明确标注“以下为推荐值，不改也能直接生成”，把默认值定义成正确答案，而不是让用户逐个研究。 |
| 等待与选择焦虑 | 生成前就显示「预计耗时」；每批产出自动标出一张「推荐」，并说明推荐理由；每张卡片带差异标签，便于横向比较。 |

## 2. 核心用户

- **内容运营**：快速生成社媒主视觉、商品图、短视频和口播素材。
- **做内容的人**：偶尔要图、要视频、要配音，但不想为一次需求买订阅。
- **多项目的人**：同时在做咖啡店、旅拍、播客，需要按项目分开，但不需要团队协作。

## 2.1 产品定位：审美积累 + 创意发散

这个工具最终要解决的不是「完成一次生成」，而是两件更长期的事：

**审美积累**——个人持续收集、筛选、沉淀自己的判断标准。AI 会越来越强，但「我知道什么好看」这件事不会外包给模型。看得多了，你才知道自己要什么。

**创意发散**——人负责产生想法，AI 负责放大它、把可能性铺开。用户给一个方向，AI 在多个方向上各试一个，用户挑，再发散。

**不做什么**：底图加字、排版套版不做——Canva 这类现成工具已经做得很好，做进来只会让这个工具变杂。它的位置在「生成与探索」，不在「排版与交付」。

**这个工具是给运营的，不是给「偶尔生成一张图的人」的。** 基础生成豆包就能做，用户不会为此换工具。运营的不同在于：他每天要出内容、要跟参考、要适配多个平台、要复用上次爆过的东西。这些事豆包做不好，才是这个工具的位置。

这两条决定了几个设计选择：

| 选择 | 因为 |
| --- | --- |
| 画板是主界面，不是表单 | 积累需要空间，不是一次性的输入框 |
| 有独立的**审美库**（跨项目、含外部内容、长期保留） | 素材库是「这个项目要交付的」，审美库是「我认可的」 |
| 核心动作是**发散**，不只是生成 | 生成是执行，发散是探索；前者要精度，后者要可能性 |
| Agent 读画板与收藏，而不是问用户 | 想法已经在画板上了，Agent 该读懂它 |

> 一句话：**生成不值钱，知道要什么才值钱**。所以产品的重心在「帮你形成判断」和「帮你看见更多可能」，不在「帮你点一次生成」。

## 2.2 创作台的三个板块

整个 AIGC 页面由三块构成，缺一块都不成立：

| 板块 | 职责 | 一句话 |
| --- | --- | --- |
| **左：生成配置** | 快速配好一次生成 | 「我要出一张图」 |
| **右：创意桌面** | 项目级的素材与思路集合 | 「这个项目我在做什么」 |
| **Agent** | 读画板，理需求，出提示词 | 「帮我把想法说清楚」 |

**左边要快**。表单是单列、紧凑的（见 3. 类型页），从进页面到点生成不超过四步，参数都有推荐默认值。

**右边不只是单次生成的落点，而是整个项目的创意桌面**。里面可能同时有：参考图、网页、视频、音频、文档、手绘标注、生成产出。这些东西随时可以被拉到左侧完成一次生成。项目结束时用户会**保存整个画板**，并输出确认的图片。

**Agent 是画板和生成之间的翻译层**。它不是凭空聊天——它的依据是画板上真实存在的东西：产出的原始提示词、参考图的标题、网页与文档的存在。它把这些汇总成「你在做什么」和「可以怎么写」。

> 三者是递进关系：**画板收集信息 → Agent 读懂信息 → 左侧据此生成 → 产出回到画板**。这条回路转起来，创作台才不只是「一个生成按钮」。

### 2.2.1 两种形态：表单态与纯画布态

生成表单可以整个收起来。收起后左栏只剩一条 46px 的竖条（保留当前类型图标和展开按钮），画布占满剩余宽度，整个页面只剩顶栏和画布——这就是「纯画布产品」的形态。

- 收起/展开：点表单头右侧的「‹」，或点左侧竖条，或按 `[`
- 状态记在本地，下次打开保持
- 收起来之后不影响任何生成能力：顶栏还有「生成」入口，画布本身能拖、能连、能分组，Agent 是浮层（见下）

**为什么要做这个切换**：这个工具真正的工作面是画板。表单只是「往里加东西」的入口，加完就该让开。默认展开是因为新用户需要引导；一旦开始整理和发散，人就会想把它收起来。

### 2.2.2 Agent 是浮层，不是表单里的一栏

Agent 从生成表单里搬了出来，改成画布右下角的一颗悬浮球：

- **收起态**：一颗球，写着「Agent」；画布上有选中时变成「分析选中 N」
- **展开态**：372px 的浮层面板，浮在画布上，不挤压任何布局
- **可拖动**：拖面板标题栏移动到任意位置
- **可停靠**：一键停靠到右侧，占满高度
- 位置和停靠状态都记在本地

**为什么搬出来**：Agent 读的是画板，不是表单。放在表单里会让人误以为它是「填表助手」；而它其实随时可用，且经常需要在画板操作到一半时叫出来。浮层才符合它的身份。

## 2.3 交互该往哪里优化

这不是功能清单，是几条判断标准。后面每加一个东西，都该拿它们过一遍。

**一、画板是唯一的工作面，左侧只是发射器。**
画板承接全部加工动作——发散、适配、定基准、连线、分组。左侧表单只做一件事：把一次生成配好。任何「需要用户先去左边做点什么」的设计都要警惕。

**二、关系比元素更重要。**
元素是素材，关系才是意图。一张图说明不了什么，「这三张是从那张参考发散出来的」才说明意图。所以画板必须能表达关系（连线），而且 Agent 必须读得到。

**三、范围即上下文。**
画板允许冗余——那是「暂存」的意义。但生成和发散时不该被冗余干扰，所以 Agent 读的是**框选的范围**，不是整块画板。

**四、工具边界在「生成与探索」。**
排版、套版、加字交给 Canva 这类工具。越界会让工具变杂，而杂是这类工具最致命的病。

**五、每一步都要能被 Agent 读到。**
画板上任何东西，如果 Agent 读不到，它就是死信息。这条决定了：加一个元素类型，就要同时想清楚 Agent 怎么理解它。

## 3. 信息架构

### 顶栏

- 项目切换（个人按项目分类，没有成员与配额）；
- 失败、队列状态（只在有任务时出现）；
- **点数余额 + 充值**（点一下直接打开充值面板）；
- 使用地图与头像。

> 导航只保留左侧一处；不再是「审批 + 提醒」那套团队治理入口——个人版没有审批流，提醒内容已并入充值与队列。

### 左侧导航（三个分组，七个入口）

**创作**——真正每天用的东西放最前面：

1. **图像创作** / **视频创作** / **音频创作**：三类工具各占一页，每页带「生成 / 编辑」两个标签。

> 画布不再占导航位，改为生成页右侧的无限画布（见 4.5），可收起。

**我的**：

3. **任务记录**：运行中、排队、失败、完成与取消的任务。
4. **素材库**：筛选、采用、收藏、下载与复用产出。

**开发与计费**：

5. **API 接入**：Key 管理、按量价格、用量账单、示例代码。
6. **模型与价格**：只读查看可用模型与单价（点数）。

> 不保留独立的“风格与预设”页面、预设数据或预设套用逻辑；也不再用一个页面里的类型切换器混装三类生成。

### Agent：读选区的那一层

Agent 常驻在生成页的提示词上方。

**它默认读的不是整块画板，而是你圈定的范围。** 这一点很重要：画板允许有冗余——那正是「暂存」的意义，乱七八糟堆着没关系的。但生成和发散的时候，这些冗余会污染判断。所以流程是：

> 在画板上**框选**一块 → 点 **分析选中** → Agent 只读这一块

没有选中时，Agent 退回到「分析整块画板」，并在入口就提示「画板有冗余时，先框选一块会更准」。分析完可以在面板底部切「改用整个画板」。

选区一变（框选松手、单击切换），已经打开的 Agent 面板会**自动重算**——否则结论和范围对不上。

点开后输出三段：

| 段落 | 内容 |
| --- | --- |
| **我看到的** | 范围内有几张图 / 视频 / 网页 / 文档 / 手绘，其中几张能追溯到原始提示词；参考了哪些平台内容 |
| **需求理解** | 从来源提示词里提取的高频关键词，加上一句方向判断 |
| **我理解的关系** | 范围里有几条连线、谁是枢纽、分组叫什么、节点上写了什么 |

底部两个动作：**用它去生成**（回填提示词与参数并切到对应类型页）、**复制提示词**。

**它的依据从哪来**

Agent 不凭空编。它读的是画板上元素背后的真实数据：

1. **产出的原始提示词**——画板上凡是来自生成的元素，都能顺着 `rid → result → job` 拿到当时那条提示词。这是最可靠的需求信号。
2. **关键词频次**——把多条提示词拆成短语统计频次，反复出现的词就是「这个项目的主方向」。
3. **元素构成**——图片 / 视频 / 网页 / 文档 / 社媒帖子各有多少，决定建议哪个类型、哪些参数。
4. **平台内容的量级**——「小红书 · 8.7k 赞」「抖音 · 12.4w 赞」，运营的判断很大程度建立在这个上。
5. **连线与分组**——统计谁连谁，**被连最多的那个就是这一组的枢纽**，通常就是基准；分组名说明用户自己怎么归类。
6. **节点与文字**——用户亲手写的话，两种都读（节点是结构件，文字是标注件，但都是直接表达）。**它的优先级高于提示词统计**：从历史提示词里数高频词只是推测，画板上的文字是用户直接说的。

**两条推断规则**

- **先定主流类型再推断**：画板上最多的那种类型决定一切。图像和视频的提示词不会混成一句——同类型不足两条时才放宽到全部，避免只靠一条过度拟合。
- **没有来源就承认没有**：画板上只有本地图片时，Agent 明说「目前只能从元素标题判断方向，补几张有来源的产出，我能读得更准」，而不是硬编一段。
- **节点文字优先于提示词推断**：提示词是历史记录，节点是当下的意图。两者冲突时以节点为准。

> 这和 v0.10 那版「构思助手」的根本区别：那版是从零开始问用户问题，这一版是**先读已有的东西**。用户已经把想法放进画板了，Agent 的工作是读懂它，不是再问一遍。

### 类型页（图像 / 视频 / 音频）

每个类型页顶部有「生成 / 编辑」两个标签，页头写明当前类型与用途。

生成标签是**单列表单**，只做一件事：写提示词、调参数、生成。页面上不再放队列和产出画廊，操作区不会被任务数量挤占；页头只留两个轻量入口「{类型}产出 N」与「队列 N」。

- 不再出现类型切换器（类型由所在页面决定）；
- 提示词输入 + 自适应辅助按钮（短句时「帮我写详细」，长句时「补充细节」）；
- 实时字数与完整度提示；
- 按类型显示必要参数：
  - **图像**：模型、比例、数量、**分辨率（1080p / 2K / 4K）**；
  - **视频**：模型、比例、时长、运镜；
  - **音频**：模型、用途、时长、音色 / 语言 / 情绪；
- 可折叠的高级参数：负面提示、随机种子、导出格式、帧率、循环点、输出音量；
- 参数区顶部固定提示“以下为推荐值，不改也能直接生成”；
- 底部依次是：本次消耗 / 余额 / 预计耗时 / 今日免费点数 → 生成按钮。

生成标签是**左右两栏**：左边是**紧凑表单**（340–410px），右边是**无限画布**（占满剩余宽度，可收起为一条 42px 竖条）。窄屏（≤1180px）自动改上下排布。编辑标签不用画布，仍是单列。

> 表单在这一版做了整体收紧：行高、内边距、控件尺寸都下调一档（表单标签列 122px → 78px、参数按钮 30px → 28px、提示词框 92px、参考缩略图 62px）。同样的信息量占更少高度，把宽度让给画布。

**分辨率就是画质。** 三档按倍率直接进单价：1080p ×0.6、2K ×1、4K ×2.2。每个模型有明确上限，选超了会在提交时报参数错误——这是真实的模型约束，不是演示规则：

| 模型 | 上限 | 单价 |
| --- | --- | --- |
| Aurora-Image F2 | 最高 1080p | 0.08 点 / 张 |
| Aurora-Image U2 | 最高 2K | 0.3 点 / 张 |
| Aurora-Image X1 | 支持 4K | 0.45 点 / 张 |

参数行右侧实时显示「该模型最高 {上限}」，用户不用去翻模型页。

> 负面提示默认收进高级参数，避免首屏堆叠过多输入区。

## 4. 核心流程

### 4.0 发散：从一个想法铺开多个方向

生成和发散是两种动作，解决的问题不同：

| | 生成 | 发散 |
| --- | --- | --- |
| 输入 | 你写好的提示词 | 画板上已有的一个素材 |
| 输出 | 同一方向的 N 张采样 | **N 个不同方向**各一张 |
| 要的是 | 精度（挑一张能用的） | 可能性（看看还能往哪走） |
| 成本 | 一次生成的钱 | 按方向数计价 |

**怎么用**：在画板上选中一个素材（图片或视频），底栏或右键点「发散」，面板里勾选要试的方向。

六个方向轴，覆盖创意发散最常用的几种「换个角度想」：

| 轴 | 换什么 | 具体做法 |
| --- | --- | --- |
| 换风格 | 视觉语言 | 改成手绘插画，笔触松弛、边缘不规则 |
| 换光线 | 打光 | 改成冷调侧光，明暗对比更强 |
| 换视角 | 机位 | 改成俯拍平铺，画面更规整 |
| 换场景 | 环境 | 放进自然光下的生活场景 |
| 换主体 | 对象 | 主体换为同品类其他对象，保持色调光线 |
| 换画幅 | 构图 | 改成竖版，主体偏上留文字区 |

默认勾选「换风格 / 换光线 / 换场景」这三个方差最大的轴，可以直接开跑。

**基础提示词从哪来**：优先用来源素材的**原始提示词**（顺着 `rid → result → job` 拿到），拼上该方向的补充描述。这样发散出来的东西和原图保持血脉关系，而不是各说各话。

**产出落在哪**：每个方向一个任务，跑完落进画板顶部的「最新生成」。任务行和结果卡上都会标出方向（`发散 · 换光线`），方便横向对比。

> **和「变体」的分工**：变体是「以这张为参考，用同一套描述再采样几张」——同方向、小方差；发散是「沿不同轴各试一个」——跨方向、大方差。要收敛用变体，要铺开用发散。两个都留着。

### 4.0.1 适配多平台：一条内容要发几个地方

运营做一次内容，通常要发好几个平台。小红书要 3:4、抖音要 9:16、公众号头图要 16:9——**用同一张图硬裁，主体不是被切掉就是被压扁**。

所以在画板上选中一个素材，右键或底栏点「适配平台」，勾选要发的平台，每个比例**重新构图出一版**：

| 平台 | 比例 | 说明 |
| --- | --- | --- |
| 小红书 | 3:4 | 封面，竖版信息流 |
| 抖音 | 9:16 | 全屏竖版，主体居中 |
| 公众号 | 16:9 | 头图横版，左右留白 |
| 微博 | 4:3 | 横版信息流 |
| 方图通用 | 1:1 | 头像 / 商品卡 / 多平台兜底 |

默认勾三个最常用的，按平台数计价（和生成同一套单价），产出落进「最新生成」，任务名标出平台与比例。

> **为什么是重新生成而不是裁剪**：裁剪只改画布大小，不改画面构成。3:4 的信息流封面需要主体偏下、上方留标题区；9:16 需要主体居中、上下都有呼吸。这两个要求靠裁同一张图做不到，必须按比例重新构图。代价是多花几份钱，但每个尺寸都成立。

**这一步放在哪完成**：**画板上**，不是左侧表单。

理由是运营的真实顺序——**先把内容做出来，再决定发哪里**。素材先有，平台后定，所以「选中一张 → 适配到这几个平台」是自然动作；反过来在生成前就要勾选所有平台，会逼用户提前做他还没做的决定，也把左侧那个「快速配好一次生成」的表单压重。

左侧表单保持简单，画板承接后续的加工动作。

### 4.0.2 系列一致性：钉住一个风格基准

一次活动要出 9 张风格统一的图。靠「每次重新描述一遍」是做不到的——描述再细，每次采样还是会有偏差。

所以在画板上选一张最满意的，右键「设为风格基准」：

- 生成页顶部出现一条基准条，显示是哪张图、沿用哪些参数；
- **此后每次生成都会自动把这张图塞进参考素材**（权重 0.75，来源标记 `anchor`），并沿用它的比例与分辨率；
- 不想用了点「取消」，或者「应用参数」只把参数搬到当前表单。

一个项目同时只钉一个基准——系列一致性靠的就是「唯一标准」。

### 4.1 图像生成

1. 选择“图像”；
2. 填写主体、场景、光线、材质和用途；
3. 选择模型、比例、数量、分辨率，可按需添加参考素材；
4. 查看预计消耗后提交生成；
5. 任务进入队列，完成后在结果卡中采用、收藏、下载或生成变体。

### 4.2 视频生成

1. 选择“视频”；
2. 填写镜头内容、节奏、光线和运动描述；
3. 选择模型、画幅、时长、运镜及是否使用首帧参考；
4. 提交后在队列中查看进度；
5. 完成后可在结果详情中模拟预览、查看参数与生成变体。

### 4.3 音频生成

1. 选择“音频”；
2. 填写口播、音乐或音效描述；
3. 选择用途、模型、时长，并根据用途设置音色、语言或情绪；
4. 提交生成；
5. 完成后在卡片和详情中查看模拟播放进度与波形。

### 4.4 失败修复

- 队列与任务记录会标出失败原因及修复建议；
- 失败原因只有两类，都是**真实存在的模型约束**，不是玄学规则：
  - `E-PRM-04`：所选分辨率超过模型上限（例如在 U2 上选 4K）；
  - `E-DUR-02`：视频时长超过模型上限（例如在 8 秒上限的模型上排 12 秒）。
- 「修复」会按建议调整参数并重新排队，同时在任务行留下「已修复」标记，写明改了什么（`4K → 2K`、`时长 12s → 8s`）；分辨率降档时**按新价重算费用**，不按失败时的高价继续收；
- 用户也可保留参数原样重试，用于对比失败分支。

### 4.5 画布：右侧无限画布

画布解决的问题是「**参考图没地方临时放，而且放不下**」——顺手存下的图、从电脑拖来的素材、还没定下来的一堆候选，需要一块随手可取的地方；同时它不该被一个固定尺寸的面板框住，所以它是一块**真正可以平移缩放的无限画布**。

**参照的对象是 PureRef**——CG 和设计圈里几乎人手一个的参考图工具。它的价值不在功能多，而在**零摩擦**：什么都能丢进去、图片就是图片（不是带标题栏的卡片）、缩放平移像呼吸一样自然、能铺满整屏专注地整理思路。

**PureRef 的灵活来自三个东西**，缺一个都会觉得「不够用」：

1. **手势**——拖空白框选、空格拖平移、滚轮缩放，手指不用离开鼠标；
2. **右键菜单**——绝大多数功能收在一个跟着选择变化的菜单里，没有工具栏要学；
3. **快捷键**——全选、复制、删除、适应窗口，都是肌肉记忆。

这三条已经全部补齐。下面「放任何东西」「图片就是图片」「专注模式」说的是内容与观感，操作方式见本节的操作表。

> **定位说明：这可能不是网页版，而是一个桌面软件。**
>
> 按软件的标准做，和按网页做，差别在几处具体的选择上：网页习惯「拖空白 = 平移」，PureRef 是「拖空白 = 框选」——这里跟了 PureRef，因为框选是批量操作的前提；网页很少用右键菜单，桌面软件离不开它；键盘快捷键在网页里可有可无，在软件里是效率的全部。原型按后者实现，将来套 Electron / Tauri 的壳不需要改交互。

位置在生成页右侧，占 46% 宽（窄屏 42%），高度铺满视口。可以收起成一条 46px 的竖条，需要时再展开。

**对齐与分布**取选区的整体包围盒做基准：左对齐是把所有元素的左边缘贴到最左边那个的左边，均分是保持首尾不动、把中间的空隙摊平。

**半透明是为了描摹**：把参考图降到 35% 垫在底下，再在上面生成或编辑，是画师的常规动作。

**放任何东西**

画布是项目的创意桌面，能接住的东西远不止图片：

| 类型 | 怎么进来 | 长什么样 |
| --- | --- | --- |
| 生成产出 | 收件箱拖进来、素材库「加素材」、结果详情「放进画布」 | 缩略图 + 类型角标 |
| 本地图片 | 拖进画布 / 顶栏 ↑ / **Ctrl+V 粘贴截图** | 图片本体，按真实比例 |
| 本地视频 | 拖进画布 / 顶栏 ↑ | 首帧 + 播放角标 |
| 本地音频 | 拖进画布 / 顶栏 ↑ | 静音波形 |
| **网页** | 拖链接进画布，或粘贴 URL | 卡片：站点 + 标题 + 完整地址 |
| **社媒帖子** | 粘贴 / 拖入小红书、抖音、微博、公众号、B 站、知乎的链接 | 卡片：平台标识 + 标题 + 作者 + 点赞 / 收藏 / 评论 |
| **文档** | 拖进画布 / 顶栏 ↑（PDF / Word / Excel / PPT / 文本） | 卡片：类型图标 + 文件名 + 体积 |
| **手绘标注** | 顶栏画笔（或按 `B`），在画布上拖动画线 | 彩色笔迹，可整体拖动删除 |
| **节点** | 右键「新建节点」，或对素材用「展开为导图」 | 可写字的卡片，思维导图的构件 |
| **文字** | 右键「新建文字」 | 无边框的标注件，用来写标题、说明、备注 |
| **分组** | 选中若干元素 → 右键「归为一组」 | 虚线容器 + 可写组名，永远垫在最底层 |

**进画板的方式只有拖入和粘贴，没有「添加」按钮**——从素材库把产出拖过来、从收件箱拖过来、从电脑拖文件进来、Ctrl+V 贴截图或网址。少一个按钮，多一条更顺的路径。

顶栏「从电脑选文件」的接受范围是 `image/*,video/*,audio/*,.pdf,.doc,.docx,.txt,.md,.csv,.ppt,.pptx,.xls,.xlsx`。

**手绘**有 5 种颜色、3 种粗细，画笔开启时画布光标变十字、顶栏出现调色条，`Esc` 或再点一次退出。每一笔是独立元素，可以整体拖走或删掉。

**社媒帖子是运营最核心的参考物**，所以单独做成一种卡片，而不是退化成一条链接。粘贴一条小红书或抖音链接，画板上出现的是带平台标识、标题、作者和互动数据的卡片——运营看的是「这条为什么爆」，数据比链接重要。

> 原型不联网，抓不到真实数据，卡片上标注了「示例」并把结构立起来。真实实现里这里接的是各平台的公开数据。

**视频链接单独处理**，分两类：

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| **直链视频文件** | `xxx.com/a.mp4` | 落成 `<video>` 元素，**画布上直接能播**——这是唯一能做到真预览的链接类型 |
| **视频平台** | YouTube / Vimeo / 腾讯视频 / 优酷 / B站 | 视频卡片：平台标识 + 标题 + **时长** + 播放量 |

视频平台和图文帖子分开，是因为运营看视频参考时看的是「时长 + 播放量」，字段不一样。

**关于其他链接的预览**：纯前端拿不到对方页面的标题和封面（跨域限制，且小红书、抖音这类还要登录态）。所以：

- **能自动的**：识别平台（小红书 / 抖音 / 微博 / 公众号 / B站 / 知乎），落成对应的卡片形态，带上平台标识与字段结构；
- **不能自动的**：标题、封面、真实互动数据。卡片上的数据标注为「示例」；
- **用户补封面**：卡片右上角有「补封面」按钮，选一张本地图就存进卡片。这符合运营的实际工作流——**看到好内容通常是先截图，再存链接**；截图已经能 Ctrl+V 进画板，链接卡片再补一张封面，两者就落到同一张卡上了。

真实实现里，这一段应该由服务端抓取（og:image / oEmbed）完成，前端只负责展示。

**保存整个画板**

顶栏「保存画板」把当前项目的画板导出成一个 JSON 文件：元素类型、坐标、尺寸、旋转、层级、来源、笔迹点全部在里面。换台机器用「导入画板」就能恢复。

> **本地文件（图片/视频/音频）不会被打包**——它们只存在于当前会话的 `blob:` 里，导出时会被跳过并明确告知。这是刻意的取舍：把几百 MB 的素材塞进 JSON 不现实，而用户的原始文件本来就在他自己电脑上，重新拖一次比搬运二进制更合理。

**项目结束时输出确认的图片**：画板上选中的产出用「保存到素材库」定稿，素材库就是交付物；画板本身是过程留档。

> v0.7–v0.16 还有「想法便签」（黄色便签，文字会并入提示词）。v0.17 移除：画布是看图的，混入文字会把「参考板」变成「笔记板」，两种心智互相干扰；写提示词有专门的输入框，不需要第二个入口。

本地图片用 `blob:` URL 只在当前会话里活着，**不上传、不进素材库、不能查生成参数**——它就是一张参考图，左下角有个灰色角标标明来源。这条边界很重要：**画布是草稿区，素材库是仓库**，混在一起用户就不敢随便往里丢东西了。

> 粘贴截图这一条是照着实际工作流加的：设计师看到竞品的一张图，第一反应是截图，第二反应是丢进参考板。要求他先存成文件再拖进来，这一步摩擦就足够让他放弃。

**图片就是图片**

元素静止时是一张纯粹的图——圆角、投影、没有边框和标题栏。类型角标和标题都**只在悬停或选中时浮出来**（标题从底部渐变压上来）。这样铺开一整屏看的时候，眼睛看到的是图与图的对比，不是一排 UI 卡片。

**专注模式**

顶栏 ⛶ 让画布铺满整个内容区、隐藏左侧表单，按 `Esc` 退出。整理思路的时候需要的是空间，不是同时盯着参数面板。

**收件箱**在画布顶部（见 4.6），是新产出的停靠点，只在有内容时出现。

**元素**

素材来自「加素材」抽屉、结果详情的「放进画布」、本地拖入或粘贴。图像 / 视频 / 音频都能放，左上角标出类型（本地图片标灰色上传角标）。

**生成参数浮层**

素材卡右上角有一个常驻的 `⚙` 按钮（AI 生成的素材才有）。点开是一张紧凑浮层，回答「这张是怎么来的」：

标题 / 模型 / 提示词全文 / 参数（比例 · 张数 · 分辨率，或时长 · 运镜）/ 参考图数量 / 消耗点数 / 来源任务 / 完成时间 / 随机种子。

编辑过的产出（没有来源任务）改为显示「来源：在编辑器中修改后保存」与改动摘要。点画布空白处或再点一次按钮即关闭。

浮层底部是两个**真正的动作**，不是装饰：

- **复制提示词**：把这条的原始提示词复制走，粘到哪都能用。
- **按这套再来一次**：提示词、模型、比例、张数、分辨率（或时长、运镜、音色）整套回填到生成表单，直接可以点生成。跨类型也成立——在图像页打开一条视频素材的参数，会切到视频创作页并把参数带过去。

> 这两个动作是「看到一张好图」之后最自然的下一步：要么拿走它的描述，要么用它再生成一批。只给一个「完整详情」的跳转，等于把用户从对比流程里踢出去。

> 做成浮层而不是跳详情页，是因为这个动作发生在「对比几张图」的过程中——用户需要的是扫一眼就能回到原处，不是被带去另一个页面。

**拖到参考素材**

画布上的素材可以直接拖到左侧「参考素材」区松手，成为生成参考：

- 拖动过程中参考区整体高亮（主色描边 + 浅底 + 提示文案变色），明确「松手就加进去」；
- 类型必须对得上：在图像页拖一个视频素材过去会提示「这是视频，当前在图像页」，不会静默失败；
- 便签不能当参考，会提示「这条不是素材」；
- 上限仍是 4 项，满了提示「先移除一项再加」；
- 松手后画布元素**回到原位**（这是「引用」，不是「移动」）。

**怎么被引用为上下文**

选中元素后底部操作条显示 `已选 3 项`，并提供**带去做图像 / 视频 / 音频**三个入口：

- 选中的素材写进该类型的参考素材（最多 4 项，缩略图标「画布」来源角标）；
- 也可以直接在画布上把素材**拖到左侧参考素材区**（见 4.5），效果相同；
- 选中的**还没保存过的产出**会多出一个「保存到素材库」按钮，把结果定稿归档。

**实现要点**

- 画布用「视口 + 世界」两层：世界层只做 `translate + scale`，网格背景用 `background-size / background-position` 跟随，所以平移缩放**不触发任何重渲染**；
- 拖动元素时直接改 `style.left/top`，松手才写回状态；
- 选中态变化只切换 class 与底部操作条，不重建节点——否则会打断正在进行的拖动；
- 视口位置与缩放按项目独立保存，切项目各看各的。

### 4.5.0 连线、分组、思维导图

这三样是一套东西，来自 Obsidian Canvas 的启发：**画板不该只是素材的堆放处，还该能表达结构。**

**连线**

- **建**：选中两个元素 → 右键「把这两个连起来」；或选中一个 → 右键「从这里连线」→ 点目标（有提示条，`Esc` 取消）
- **看**：细灰曲线 + 箭头；鼠标移上去变主色
- **选与删**：点线选中（加粗高亮），`Delete` 删除；删掉元素时挂在它身上的线自动清理
- **跟随**：拖动元素时线实时重算，不会脱节
- **技术细节**：每条线渲染成两条同形状的 path——细的负责看，16px 透明加粗的负责点得中（1.8px 的线实际点不中）；SVG 视口设为 `-2000,-2000` 起、8000×8000，否则画在视口外的线能看不能点

**分组**

- 选中若干元素 → 右键「归为一组」，自动按包围盒生成虚线容器（留 26px 边距 + 30px 标题栏）
- 组名直接点着改；标题栏右侧显示组内元素数
- **永远垫在最底层**（`z-index` 用 `-1000 + z`），不会遮挡元素
- 拖标题栏 → 组内元素一起移动
- 空画板右键菜单里有「把画板上的东西归为一组」

**节点与思维导图**

节点是**可写字的卡片**，思维导图的构件。三个入口：右键「新建节点」、空画板菜单、以及对素材用「展开为导图」。

「展开为导图」会以选中素材为中心，向右生成 6 个方向节点（沿用发散的全部六个轴：换风格 / 换光线 / 换视角 / 换场景 / 换主体 / 换画幅）并自动连线——一键得到一张导图骨架，节点文字直接改。

**再点一次就是重新布局**：上一次由导图生成的节点会被撤掉重排，你自己手动加的节点不动，也不会重复建。

> **节点和 v0.17 删掉的「便签」不是一回事。** 便签是散落的碎片：随机位置、黄色斜贴、写什么都行，结果把参考板变成了笔记板。节点是**结构件**——视觉上是规整的图节点，创建后立刻引导你连到别的东西上。它不会退化成笔记板，因为它天生要参与结构。

**给线写名字**

线只表示「有关系」是不够的——「参考」「变体」「来源」是不同的关系。右键点线 → 「给这条线写个名字」，输入框贴在曲线中点，回车或点「确定」保存，最多 12 个字。写了名字的线会在中点显示一个标签。

标签画在**元素上面**（线本身在元素下面，这样卡片能压住线才清爽；但名字是内容，被卡片盖住就白写了）。Agent 读画板时会带上这些关系名：「你给线写了「参考」「变体」——这些关系我会照着理解。」

**发散 / 适配的产出自动连线**

从某张图发散或适配出来的产出，拖进画板时会**自动连回源元素**（任务上记了 `fromCvsId`）。所以发散的结果天然就是一张有结构的图，不需要手动连。

### 4.5.0.1 文字：画板上的标注件

画板上有两种能写字的元素，用途不同：

| | 节点 | 文字 |
| --- | --- | --- |
| 长相 | 白色卡片，有边框、圆角、阴影 | **什么都没有**，就是文字本身 |
| 身份 | 结构件 | 标注件 |
| 创建后 | 引导你连线，参与导图 | 不连线、不参与导图 |
| 用来做什么 | 「换光线」「留白多一点」这类**要参与结构**的方向 | 「春季新品」「主视觉走暖橙」这类**解释和标注** |

**怎么用**：右键空白画板 → 「新建文字」。建完直接进编辑状态，打完字点别处就保存。

**编辑**：双击进编辑（`contenteditable`），点别处或按 `Esc` 退出。平时单击是选中和拖动，不会误触输入。

**它真的只是文字。** 不画框、不铺底、不给拖拽手柄——静止、选中、编辑三种状态下**都没有任何容器感**，因为任何容器都会让它在画板上看起来像一张卡片。

**宽度由内容决定**：短句贴着字走，最长到 420px 后折行。所以它不会顶着一个固定宽度的空盒子，旁边也不会挂着多余的方框。

**字号三档**（右键文字 → 字号）：

| 档位 | 大小 | 用途 |
| --- | --- | --- |
| 小 | 11.5px 灰 | 备注、说明 |
| 中 | 13.5px | 正文 |
| 大 | 19px 加粗 | 标题、分组名 |

**宽高实测回写**：渲染完量一次真实尺寸写回数据，所以框选、分组、连线端点用的都是真实边界，而不是估计值。

> **代价**：选中文字时没有任何视觉反馈（没有框、没有角标），只能靠底部操作条的「已选 N 项」和光标形状判断。这是「文字就是文字」的直接代价——如果想要一个极轻的提示（比如文字底色），说一声就加。

> **为什么和 v0.17 删掉的「便签」不是一回事。** 便签的问题是三样：随机位置、黄色斜贴、写什么都行——结果把参考板变成了笔记板。文字元素是**有明确用途的排版元素**：位置由你放，样式克制（没有颜色和贴纸感），而且分三档字号对应三种明确的用途。它不抢结构（不连线、不参与导图），只负责解释。

### 4.5.0.2 画板会被记住，而且可以撤销

**画板持久化。** 画板是这个工具真正的工作面，不能刷新一次就没了。素材库、帖子、界面偏好都记得住，画板没理由记不住——所以现在每改一次画板（改完 350ms 内）就写进本地，刷新、关标签、第二天再打开都还在。序号会接上，新建的元素不会和恢复的撞 id。

唯一恢复不了的是**从电脑拖进来的本地文件**：它们是临时引用（blob URL），刷新后必然失效。这种情况会明确告知「有 N 个本地文件没能恢复」，而不是静默丢掉。存进素材库的产出不受影响。

**撤销 / 重做。** `Ctrl+Z` / `Ctrl+Shift+Z`（或 `Ctrl+Y`），画布工具栏左上角也有两个按钮，没得撤的时候是灰的。每个项目独立一份历史，最多 40 步。

实现方式是**自动快照**而不是给每个动作手写回滚：画布每次稳定下来就比一次快照，和上一版不同就压栈。好处是拖动、批量对齐这类多步操作只记一步，而且不用每加一个功能就记得补一段撤销逻辑。

### 4.5.1 审美库：长期积累的那一层

**它和素材库不是一回事。**

| | 素材库 | 审美库 |
| --- | --- | --- |
| 装什么 | 这个项目产出的、要交付的东西 | 我个人认可的、代表我品味的东西 |
| 范围 | 按项目隔离 | **跨项目** |
| 来源 | 只有生成产出 | 生成产出 + **外部内容**（本地图片、网页） |
| 生命周期 | 项目结束就归档 | **长期留着** |
| 用途 | 交付 | 形成判断标准 |

**怎么收进来**：画板元素右键「收进审美库」、素材库卡片点收藏、或审美库页面「从电脑收藏」直接收外部图片。

**外部内容怎么长期保存**：收藏时把图片压成 420px 的缩略图存进 `localStorage`，所以一张从网上存下来的图也能一直留在库里，不依赖原文件还在不在。生成产出则直接引用素材路径，不重复存。

**去重靠 key**：生成产出用 `r:结果id`，本地文件用 `f:文件名:大小`，网页用 `w:url`。同一件东西不会收两次。

**持久化**：整个审美库存在 `localStorage`（键 `aigc-studio-aesthetic-v1`），刷新和重开都还在——这是「长期」这个承诺的技术落点。

### 4.6 产出怎么流转：收件箱 → 画布 → 素材库

产出不是生成完就直接进素材库的。中间隔着「你要不要它」这个判断，画布就是做这个判断的地方。

```
生成  ──►  收件箱（画布顶部）  ──拖进画布──►  画布（对比、修改）  ──保存──►  素材库
                    │
                    └──没被拖走的，下次生成时自动沉入──►  草稿箱
```

**收件箱**：新生成的结果停在画布顶部的一条横条里，显示「最新生成 N 项」和缩略图。用户在这里做唯一一个决定——**留，还是不留**：

- **留**：把缩略图拖到画布上（或点缩略图右下角的 `+`）。落点就是你松手的位置。
- **不留**：什么都不用做。下次生成新一批时，上一批还在收件箱的自动沉入草稿箱。
- 也可以主动点「全部不收」一次性清空当前项目的收件箱。

**画布**：拖进来的东西在这里被对比、修改、组合。选中的元素可以「带去做图像 / 视频 / 音频」继续生成，也可以「保存到素材库」定稿。

**素材库**：只装被确认保存的产出。已保存的元素在画布上会带一个绿色的「已存素材库」标记——它不会从画布上消失，因为画布是工作台，素材库是归档，两件事。

**草稿箱**：生成后没被拖进画布的内容都落在这里。**它们没有删除**，只是没被选中——想用可以「捞回画布」继续加工，也可以直接「存进素材库」。

> **为什么不是「自动删除」**：生成是花钱的，用户对「我的东西被系统删了」极度敏感。草稿箱保留了全部内容，只是把它移出主视线——这既达到「不被废弃内容干扰」的目的，又不制造任何不可逆的操作。
>
> **与 v0.8「最近一批」的区别**：那时是一条只读的横条，告诉用户「刚生成的东西在哪」；现在这块地方是可操作的收件箱，是产出流转的第一站。「最近一批」被删掉过一次（v0.10），因为它是额外的信息条；收件箱能立住，是因为它承担了一个必须有人做的判断。

### 4.6.1 素材库：编辑、打包、成帖

素材库不只是「存起来」，它是**从素材到成品的那一段**。

**编辑产出**：每张卡片悬停后右上角有「编辑」笔形按钮，打开抽屉可以改三样东西：

| 字段 | 作用 |
| --- | --- |
| **标题** | 卡片上显示的名字。默认是模型自动生成的，改成你自己的说法 |
| **说明** | 这条打算怎么用——发哪个平台、配什么文案。写给自己看的 |
| **标签** | 空格分隔。会显示在卡片上，也是 Agent 读画板时的关键词来源 |

抽屉里同时显示**原始提示词**（只读），方便对着改。

**打包成帖**：卡片左下角有勾选按钮。勾选 ≥2 项后，筛选栏下方出现操作条「已选 N 项 · 打包成帖」。点下去就生成一条**帖子草稿**：

- **标题**：默认取第一条产出的标题，可改
- **正文**：多行文本，带实时字数
- **配图顺序**：打包进来的产出，**可拖动排序**（拖到谁身上就排在谁前面），每张也可用 ← → 前移后移、✕ 移除，还能从素材库继续加
- **目标平台**：小红书 / 抖音 / 微博 / 公众号 / B站 / 知乎，只是记下打算发哪儿
- **导出**：导出 Markdown（图片指向 `assets/results`），或一键复制正文

帖子草稿落在素材库新增的**「帖子」分桶**（素材库 / 草稿箱 / 帖子）。草稿箱装「还没决定要用的产出」，帖子装「已经攒成一条内容的成品」——两者是不同的东西，所以分开放。

**存在本地**：产出的标题/说明/标签，和帖子草稿，都写进 `localStorage`。产出本身是原型内的种子数据，刷新会回到初始状态；但**你改过的和你攒出来的不会丢**。

> **不做什么**：不接真实发布接口、不做富文本编辑器、不做封面裁切。这里只负责把「素材」变成「一条能发的内容」，发布是下一个工具的事。

### 4.7 队列与产出放在哪里

生成、编辑、看结果三件事拆开放在不同位置，避免互相干扰：

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 生成队列 | 顶栏「队列」芯片，或类型页页头「队列 N」→ 右侧抽屉 | 抽屉按需展开，不占用操作区；任务再多也只是抽屉内滚动。顶部固定显示「生成中 / 排队 / 失败」计数与「全部 / 只看失败」切换，底部提供「查看全部任务」 |
| 失败任务 | 顶栏「失败」芯片 | 打开同一个抽屉但默认只看失败，便于直接修复重试 |
| 任务记录 | 左侧「任务记录」 | 全部任务（含昨天），可按全部 / 失败 / 进行中筛选，展开行查看失败原因与产出清单 |
| 生成产出 | 左侧「素材库」，或类型页页头「{类型}产出 N」 | 类型页的产出入口会自动带上该类型的筛选条件，方便只看本类结果 |

规则：

- 生成入队后不清空提示词，可以连续排队，队列在抽屉里看；
- 任务完成后用 Toast 告知，并说明产出已进入素材库，不强行占据当前页面；
- 抽屉打开时 Toast 会自动上移，不会挡住抽屉底部按钮；
- 队列不提供「清理」动作：已结束的任务只存在于任务记录，历史不会被任何一步隐式删除。

### 4.8 基础编辑

每个类型页的「编辑」标签提供一个只做简单处理的编辑器，进入时默认选中该类型最新的一条产出：

| 类型 | 可做的处理 |
| --- | --- |
| 图像 | 滤镜（原图 / 暖调 / 冷调 / 黑白 / 胶片）、水平与垂直翻转、亮度 / 对比度 / 饱和度（-50 ~ +50）、裁剪比例（决定导出规格） |
| 视频 | 裁剪时长（入点 / 出点）、变速（0.5x / 1x / 1.5x / 2x）、静音、封面帧（首帧 / 中间 / 末帧）、叠加字幕 |
| 音频 | 裁剪时长（入点 / 出点）、音量（0 ~ 150%）、淡入、淡出、降噪、响度标准化 -3dB |

编辑规则：

- 预览区是固定高度的舞台，图像按目标比例给出裁剪框，视频与音频按原始比例居中显示，不会因为竖版素材把页面撑长；
- 拖动滑块只刷新预览，不会整页重绘；
- 底部常驻参数摘要（`滤镜 黑白` `亮度 +20` `保留 00:05 – 00:15 · 10s`），任何改动都能立刻看到结果；
- 点「保存为新产出」会生成一条标记为「已编辑」的新产出，**原素材保持不变**；
- 入点与出点会自动收敛到当前素材的合法区间，避免出现滑块与数值不一致；
- 视频与音频预览上方有播放条，可直接试看 / 试听当前剪辑结果（本地模拟，进度与波形着色同步推进）。

### 4.9 产出挑选

- 每张结果卡展示两个差异标签（如「低饱和」「平铺」），新产出额外带「新」徽章，打开详情后消失；
- 每张卡的元信息行带项目标识（色点 + 名称），跨项目浏览时不会认错归属；
- 用户自由决定采用哪一张，系统不替用户做选择。

> **关于「自动推荐一张」**：v0.4 曾计划每批自动标一张「推荐」，v0.7 起评分函数失去调用点，v0.10 正式移除这段死代码与对应 UI。原因是推荐依赖「按批查看」的场景，而每批视图已在同一轮被删除——在一张平铺的素材库里标「推荐」既没有对照组，也没有说服力。系统不替用户选，是这一轮「不要过度设计」的一部分。

### 4.10 产出复用

- 对已生成的图片、视频或音频点击“变体”；
- 系统将该结果回填为当前类型的参考素材，并带入来源任务的提示词；
- 用户在创作台补充描述后再次生成。

## 5. 状态与业务规则

### 任务状态

- `queued`：等待执行；
- `running`：执行中，显示模拟进度；
- `succeeded`：已完成并产生结果；
- `failed`：失败，队列中直接给出原因与修复建议；
- `canceled`：已取消。

### 产出状态

两层状态，一层管「在哪」，一层管「选了没」。

**位置（`home`）**

| 值 | 含义 | 出现在 |
| --- | --- | --- |
| `inbox` | 刚生成，等用户决定 | 画布顶部收件箱 |
| `canvas` | 已被拖进画布留用 | 画布 |
| `library` | 已确认保存 | 素材库（同时可能仍在画布上） |
| `draft` | 生成后没被取用 | 草稿箱 |

流转：`inbox → canvas`（拖进画布或点 +）、`inbox → draft`（下次生成时自动）、`draft → canvas`（捞回画布）、`draft → library`（存进素材库）、`canvas → library`（保存到素材库）。**没有任何一步会删除产出。**

**选中状态（`status`）**：`new` 待选 / `adopted` 已采用 / `fav` 已收藏。

### 点数与计费

**1 点 = ¥1**，按次扣费，没有订阅、没有月费、没有日配额。

- 余额不足时，生成按钮直接变成「点数不足 · 去充值」，点开充值面板；
- 充值档位 ¥10 / ¥30 / ¥100，**首充翻倍**（每人一次）；
- **每日免费点数 0.5 点**，当日有效、不累积，生成时**优先抵扣**，再扣余额；
- 任务**创建时即扣费**；取消任务——无论排队中还是生成中——都会退回，按钮提示与实际一致；
- 重跑与修复重试按同一口径重新扣费，用 `charged` 标记保证「取消 → 重跑」的净支出正好等于一次费用，不会双重扣费；
- 失败任务不扣费（参数校验不通过时根本不入队）；
- 任务记录页的「实际消耗」只统计已成功任务的费用，不含失败与已取消。

给用户的三条承诺（写在充值面板里）：**点数不过期、生成失败自动退回、产出可直接商用**。

价格表按「点」标价，同时给出人民币换算与具象场景（如「生成 4 张标准图约 1.2 点」），避免抽象单价让人算不清。

### 项目口径

- 任务、画布按项目隔离；
- 素材库、编辑器的素材池**默认只看当前项目**，可切换「全部项目」，切换同时作用于列表与计数；
- 每个产出卡片、编辑选材条、画布「添加素材」抽屉都带项目标识（色点 + 名称）；
- 类型页页头的「{类型}素材 N」与左侧导航的类型徽标**只数素材库里已保存的**，与素材库页一致；
- 收件箱、画布按项目隔离；素材库与草稿箱默认当前项目，可切「全部项目」；
- 顶栏「失败 / 队列」芯片、队列抽屉计数、素材库与任务记录徽标仍是全局口径（跨项目汇总），后续统一。

### API 接入（专业用户线）

一个页面解决专业用户关心的全部问题：

| 区块 | 内容 |
| --- | --- |
| 余额条 | 与网页共用的点数余额，今日调用次数与消耗 |
| 密钥 | 创建、复制、停用/启用、删除；只显示掩码；每条标注所属渠道 |
| 按量价格 | 每个模型的单价（点 / 计价单位）、常见用法、折合人民币、所属渠道 |
| 用量与账单 | 按调用时间列出次数与消耗，底部合计 |
| 快速开始 | curl / Python / Node 三份可直接复制的示例代码 |
| 渠道 | 渠道列表、说明与覆盖模型数 |

规则：**网页与 API 共用同一份余额，不额外收费**；调用失败不扣费；超出并发上限返回 429。

**模型渠道（基础设施层）**

模型不是直连各家原厂的，而是经过**渠道层**统一接入、路由与计费。原型里定义了两个渠道：

| 渠道 | 说明 | 覆盖 |
| --- | --- | --- |
| 聚合网关 | 统一入口，多供应商自动路由与故障切换 | 6 个模型 |
| 官方直连 | 直连原厂，延迟更低、规格更完整 | 2 个模型（Muse-Video C1、Aurora-Image X1） |

**Key 按渠道签发**——换渠道要换 Key；同一能力可能有多条渠道可选，按延迟与成本自行取舍。这一层是「模型 → 渠道 → endpoint」映射的落点，将来接真实供应商时不需要重构数据。

> **渠道命名是刻意的中性词**。创作台面向终端用户，不暴露底层供应商品牌——用户看到的是「聚合网关 / 官方直连」这种规格描述，而不是某家服务商的名字。真实供应商（例如 TreeCloud 这类聚合平台）挂在渠道背后，属于内部信息。

## 6. 原型数据与模拟边界

- **不调用真实生成模型**：排队、进度、成功、失败、计费、下载和播放均为本地模拟。
- **结果素材**：图片、视频封面和音频封面为 GPT Image 2.5 生成的本地示意素材；视频和音频播放不包含真实媒体文件。
- **失败规则**：所选分辨率超过模型上限、或视频时长超过模型上限时失败——这两条与真实产品的模型约束一致，不是人为规则。
- **参考素材**：添加参考素材使用已有示意素材代替真实上传。
- **画布与产出流转**：三个项目各预置了一块示例画布（图 / 视频 / 音频混排）与若干素材库、草稿箱内容，用于演示「收件箱 → 画布 → 素材库」的完整链路；元素坐标、视口与位置状态都只在本地状态里，刷新即重置。
- **失败演示之外无随机性**：产出落点完全由用户操作决定，没有自动删除或自动归档。
- **数据持久化**：刷新页面将恢复初始演示数据。
